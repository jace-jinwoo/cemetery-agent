# 결정

2026-10-19 업무 정책을 도메인 기준으로 반영한다. `확인 필요`와 법적 근거가 없는 산식은 확정하지 않는다. 원본에 없는 숫자는 기본 제안이며 묘원 설정으로 바꾼다.

## 확정한 기술 판단

1. 제품명은 묘원에이전트다. Figma의 묘원365는 프로토타입 이름이다.
2. 앱은 저장소 루트의 Next.js다. `reference/`는 참조만 하고 빌드하지 않는다.
3. 디자인 이미지에서는 어두운 사이드바, 상단 검색, KPI 카드, 흰 카드, 밀집 표, 필터, 상태 배지만 가져온다.
4. 배경색은 `#F3F6F4`다.
5. 통계와 리포트는 메뉴를 나눈다. 통계는 차트, 리포트는 기간 집계와 다운로드다.
6. Prisma 모델명은 영어 도메인 이름, 테이블은 snake_case다. `transactions` → `contracts`, `mausoleums` → `plots`, `dead` → `deceased`.
7. 테넌트 키는 `cemetery_id`다. 세션 소속으로 정한다.
8. 운영 데이터의 물리 삭제는 쓰지 않는다. `deleted_at`은 현재 행의 은폐용이다.
9. 계약, 묘역 배정, 안치, 수납, 해약·이장 이력은 추가만 한다. 덮어쓰거나 삭제하지 않는다. 정정은 상계·신규 이력이다.
10. 금액은 원 단위 `Decimal(14, 0)`이다.
11. 감사 로그와 계약 이력 JSON에 주민등록번호와 전화번호 원문을 넣지 않는다.
12. 주민등록번호는 컬럼 하나다. 저장 시 암호화하고 화면은 마스킹한다. 기본 필수 입력이 아니다.
13. 전자서명 상태는 계약 상태와 분리한다. 연동 사양 전에는 전이를 구현하지 않는다.
14. `id`를 PK로 한다. `profile_image_url`은 일반 컬럼이다.
15. 소스의 `udpated_at`, `udpated_by`는 `updated_at`, `updated_by`다.
16. 주소는 `zip_code`, `address`, `road_address`, `address_detail`을 유지한다.
17. `search_history`, `search_histories`와 묘역 도면 좌표 테이블은 컬럼이 없어 만들지 않는다.
18. Figma 샘플 인명, 전화번호, 금액은 시드에 복사하지 않는다.
19. 파일은 S3 object key만 저장한다. 기본 제한은 PDF/JPEG/PNG, 20MB다.
20. 인증은 Auth.js Credentials다. SaaS 운영자 세션과 묘원 소속 세션을 구분한다.
21. Phase 1 전역 검색은 비활성이다.

## 확정한 업무 정책

### Q1. 인물과 역할

계약자, 신청자, 연고자는 묘원 공통 인물 명부(`persons`)를 쓰고, 계약별 역할은 `contract_parties`에 둔다. 한 사람의 복수 역할을 허용한다.

`is_primary_contact`는 주 연락처 표시다. 계약자 역할을 대체하지 않는다.

신청자2/3는 레거시 UI 슬롯으로 `legacy_slot`에 보존한다. 그 번호의 원본 의미는 확인 필요.

역할별 최소·최대 인원은 정책에 없다. 제한을 코드에 넣지 않는다.

### Q2. 안치자와 연고자

안치자와 인물은 N:M이다. `deceased.acquaintance1_id`, `acquaintance2_id`는 만들지 않는다.

고인과의 가족관계는 `family_relationships`에 둔다. 계약자나 역할이 바뀌어도 가족관계를 자동으로 바꾸지 않는다. 변경은 새 이력이다.

### Q3. 예정지와 사용 계약

예정지 계약 행은 유지한다. 사용 전환은 그 행의 유형을 덮어쓰지 않고, 연결된 사용 계약 행을 만든다.

묘역 배정과 관련 인물 연결은 사용 계약으로 승계한다. 승계는 예정지 쪽 이력을 지우지 않는다.

기존 입금 행은 예정지 계약에 둔다. 사용 계약과는 정산 연결로 잇는다. 입금 행을 사용 계약으로 옮기지 않는다.

### Q4. 묘역 배정과 이장

배정은 `plot_assignments` 이력이다. `plots`에 현재 계약 FK 하나를 두지 않는다.

계약은 여러 묘역을 가질 수 있다. 묘역은 기간을 달리해 여러 계약에 배정될 수 있다.

이장은 내부 이동과 외부 이장을 모두 기록한다. 완료돼도 묘역을 판매가능으로 바꾸지 않는다. 재사용은 현장 확인 이력이 난 뒤에만 가능하다.

`plot_node_id`는 값을 보존할 자리만 둔다. 묘역 FK로 해석하지 않는다. 의미는 확인 필요.

### Q5. 수납

수납 원장은 청구 항목, 입금, 충당이다. 약정 금액 라인과 분리한다.

부분납부와 여러 번의 입금을 허용한다. 충당 기본 순서는 지정 청구 우선, 지정이 없으면 오래된 미납 청구 우선이다. 이 순서는 기본 제안이며 묘원 설정으로 바꾼다.

관리비 회차와 분할납부 회차는 다른 컬럼이다.

장기미납은 묘원 설정이다. 기본 제안은 90일 또는 2회이며, 둘 다 설정값이다. 법령상 기준으로 확정하지 않는다.

화병은 석물 항목이다. `vases` 테이블은 만들지 않고 석물 필드로 매핑한다.

납부수단의 닫힌 목록은 없다. 묘원 설정 코드로 두고, 임의 코드를 필수로 박지 않는다.

### Q6. 주민등록번호

`ssn`과 `resident_number`를 한 컬럼으로 합친다. 전체 번호 수집은 기본 필수가 아니다.

법적 근거가 기록된 업무에서만 최소 수집한다. 근거, 대상 업무, 전체 번호 열람 권한의 법적 범위는 확인 필요. 그 전에는 입력란을 필수로 두지 않고, 기본 열람 권한도 주지 않는다.

### Q7. 상태

다음을 서로 다른 축으로 둔다.

- 계약 상태: 화면 기준 상담, 예약, 계약, 해약
- 계약 유형: 신규, 이장, 해약, 예정지. 현재 상태가 아니라 사건 분류다
- 묘역 상태: 화면 기준 판매가능, 예약, 계약, 설묘, 안치, 이장, 사용불가
- 안치 상태: 묘역 상태와 별도. 허용 값 목록은 확인 필요
- 서명 상태: 연동 상태. 계약 상태에 넣지 않는다

해약·이장 완료 시 묘역을 판매가능으로 자동 변경하지 않는다. 상태 조합의 나머지 자동 전이는 확인된 규칙이 없다. 임의 전이를 만들지 않는다.

화면 묘역 상태의 설묘·안치와 별도 안치 상태를 어떻게 겹쳐 쓸지는 확인 필요.

### Q8. 번호

회원번호, 계약번호, 묘적번호, 예정지계약번호는 서로 다른 번호다. 묘원별 채번과 형식 설정을 둔다. 이미 있는 번호는 재채번하지 않는다.

소스 `mausoleums.member_number`는 묘적번호와 회원번호가 한 컬럼으로 적혀 있다. 기존 값을 두 번호로 자동 분배하지 않고 원본 값으로 보존한다. 어느 번호인지는 확인 필요.

전체관리번호, 사용회원번호는 위 네 번호와 같다고 보지 않는다. 확인 필요.

### Q9. 권한

묘원 기본 역할은 묘원 관리자, 계약 담당자, 수납 담당자, 현장 담당자다. Figma의 시스템관리자·묘역관리자 이름과 체크표는 운영 정책이 아니다.

역할마다 기본 권한을 두고 묘원이 조정한다. 한 사용자의 복수 역할을 허용한다.

SaaS 운영자는 묘원 관리자와 다른 주체다. 운영자에게 묘원 개인정보 열람을 기본으로 주지 않는다. 지원 목적의 열람 절차는 확인 필요.

기본 권한표는 아래 제안이다. 묘원 설정으로 바꾼다.

| 메뉴 | 묘원 관리자 | 계약 담당자 | 수납 담당자 | 현장 담당자 |
| --- | --- | --- | --- | --- |
| 대시보드 | 허용 | 허용 | 허용 | 허용 |
| 계약 | 허용 | 허용 | 조회 | 없음 |
| 묘역 | 허용 | 허용 | 없음 | 허용 |
| 수납·청구 | 허용 | 조회 | 허용 | 없음 |
| 상담·민원 | 허용 | 허용 | 없음 | 허용 |
| 해약·이장 | 허용 | 허용 | 없음 | 허용 |
| 통계·리포트 | 허용 | 허용 | 허용 | 없음 |
| 설정 | 허용 | 없음 | 없음 | 없음 |

주민등록번호 원문 열람은 이 표에 넣지 않는다. 기본값은 불가.

### Q10. 환불

환불금액은 담당자가 산정하고 묘원 관리자가 승인한다. 산식 엔진은 나중에 묘원별 규칙으로 붙일 자리만 둔다.

실제 산식은 적용 법령, 계약서, 묘원 규정이 확인되기 전에는 구현하지 않는다. 자동 계산 결과를 환불액으로 저장하지 않는다.

## 확인 필요

- 신청자2/3 레거시 번호의 원본 의미
- `plot_node_id`의 의미
- 주민등록번호를 수집하는 업무와 법적 근거, 원문 열람의 법적 범위
- 안치 상태의 허용 값
- 묘역 상태의 설묘·안치와 안치 상태의 관계
- 소스 `mausoleums.member_number`가 묘적번호인지 회원번호인지
- 전체관리번호, 사용회원번호의 의미
- 납부수단 코드의 표준 목록
- 석물 유형 표기 묘태/묘테의 동일 여부
- `dead.tomb_type`이 묘역 유형과 같은지
- SaaS 운영자의 묘원 데이터 지원 열람 절차
- 해약 환불 산식
- 계약 상태와 묘역 상태의 자동 전이. 해약·이장 완료 시 판매가능으로 바꾸지 않는 것만 확정

## 기본 제안값

묘원 설정에 두고 코드에 고정하지 않는다.

- 충당 순서: 지정 청구, 없으면 오래된 미납 청구
- 장기미납: 90일 또는 2회
- 채번 형식: 묘원별 패턴. `M2024-0001`은 샘플이며 기본 형식이 아니다
- Q9의 메뉴 권한표
