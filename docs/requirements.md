# 요구사항

제품: 묘원에이전트. 묘원 단위로 데이터가 격리되는 B2B SaaS.

기준 우선순위: 구현 조건 > `reference/data-model.md` > Figma 메뉴·업무 흐름 > 디자인 이미지의 시각 스타일.

디자인 이미지의 이커머스 메뉴, 지표, 샘플 데이터는 요구사항이 아니다. Figma 프로토타입의 인명·금액도 요구사항이 아니다.

전자서명, 문자/알림, PG 결제는 인터페이스만 둔다. 연동 사양과 자격 증명이 없으면 완료로 보지 않는다.

## 메뉴

- [ ] 대시보드: 신규 계약, 예약, 납부 확인, 관리비 청구 예정, 미납, 장기 미납, 상담·민원, 이장 예정, 해약, 묘역 현황, 계약 현황, 수납 현황
- [ ] 계약 목록: 회원번호, 계약자, 안치자, 묘역번호, 연락처, 등록일, 관리종료일 검색. 계약 상태, 관리 상태, 납부 상태, 묘역 상태 필터. 정렬, 페이지네이션
- [ ] 신규 계약: 기본정보, 묘역·설묘, 안치자, 비용, 관리기간, 저장
- [ ] 계약 상세 탭: 계약정보, 안치자, 묘역, 비용, 납부, 관리비, 상담·민원, 메모, 해약·이장, 문서
- [ ] 계약 수정과 계약 이력
- [ ] 묘역 현황: 단지, 구역, 도면, 위치, 상태. 위치 선택 시 계약 조회
- [ ] 묘역 예약
- [ ] 예정지 계약과 사용 전환
- [ ] 납부 내역, 청구, 관리비, 장기 미납
- [ ] 부분납부와 여러 차례 입금
- [ ] 상담·민원·조치 기록
- [ ] 해약, 이장, 상태와 이력
- [ ] 문서 첨부 (S3 presigned URL)
- [ ] 통계 차트
- [ ] 리포트: 계약, 묘역, 수납, 관리비, 미납, 해약. Excel/PDF
- [ ] 설정: 단가, 사용자, 권한, 공원정보, 알림 조건

알림 설정은 조건 저장까지다. 실제 발송은 연동 사양이 생기기 전에는 완료가 아니다.

## 필수 업무 시퀀스

1. 신규 계약 → 묘역 배정 → 안치자 → 비용 → 저장 → 상세
2. 계약 검색 → 상세 → 수정 → 이력 저장
3. 관리비 산정 → 청구 생성 → 납부 처리 → 잔액 반영
4. 미납 조회 → 상담·조치 기록
5. 묘역 현황 → 위치 선택 → 계약 조회
6. 예정지 계약 → 사용 전환
7. 해약·이장 → 상태와 이력 반영

Figma에 있는 전자서명 흐름(생성, 서명요청, 서명완료, 반려, 재요청)은 연동 대기 흐름으로만 기록한다.

## 완료로 보지 않는 것

버튼만 눌리거나, 샘플 배열만 보여주는 화면은 완료가 아니다. 완료는 실제 DB, 서버 검증, Tenant 검증, 권한, 검색·필터·페이지네이션, 로딩·빈 화면·오류, 관련 테스트, 화면 간 데이터 정합성이 갖춰진 상태다.
